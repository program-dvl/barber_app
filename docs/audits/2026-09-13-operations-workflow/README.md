# Front-desk operations workflow audit

Audit date: 2026-09-13  
Scope: Location setup, team setup, calendar, walk-in queue, manual checkout,
transactional email and reports.  
Health: **Healthy for the implemented local release.** Provider delivery still
depends on deployment mail credentials and the scheduler running every minute;
online payment, WhatsApp/SMS and user-facing inventory remain intentionally
outside this release.

## 1. Baseline review

The existing implementation was inspected before modification against the
canonical Location, Membership/StaffProfile, Client, Appointment, Sale,
OperationalNotificationEvent and reporting services. The baseline screenshots
are retained beside this report:

Largest friction points: unclear multi-location expansion, free-text-only team
titles, redundant calendar modes, non-proportional scheduling, fragmented visit
actions, detached walk-in identities, implementation-oriented checkout, and a
report picker that exposed product/stock reports ahead of the visible workflow.

## 2. Information architecture

The calendar now uses three purposeful modes: Day for one focused schedule,
Week for seven date columns, and Team for provider columns. Today is a shortcut,
not a fourth copy of Day. A selected appointment opens one action surface rather
than placing many small actions on every event.

Location, team, queue, checkout and report work remain separate focused
workspaces. Plan restrictions and optional future capabilities are explained at
the point of action without blocking unrelated work.

## 3. Calendar behavior

The schedule uses the selected Location's local time. A 09:30–10:30 appointment
starts halfway between the 09:00 and 10:00 lines and ends halfway between 10:00
and 11:00. Duration controls event height, overlapping events receive separate
lanes, and the empty grid remains visible. Current time is marked when the date
is today.

Reschedule, resize, reassign and service changes revalidate capacity through
the existing replacement engine. The previous appointment version stays in
history but no longer appears as a second active booking. Cancellation requires
a reason, releases capacity, queues notification intent, and remains discoverable
through the cancelled status filter.

## 4. Client and walk-in integrity

The Add walk-in dialog starts with an existing-client search and offers a clear
New client alternative. A new walk-in client is created immediately in the CRM
transaction and linked to the queue entry; later conversion reuses that Client.
Search and creation remain tenant scoped and permission guarded.

## 5. Checkout, communications and reports

Completed unpaid visits enter an appointment-first checkout list. The current
release shows only manual confirmation methods and never claims to process an
online/card payment. Completion is idempotent, issues a receipt, creates one
payment-receipt event and feeds source-linked reports.

Transactional email is generated by default where an email exists and honours
an explicit appointment- or client-level email opt-out. The existing scheduled
event processor runs every minute. User-facing report navigation includes the
implemented appointment, sales, service/staff revenue, payment, location,
discount, refund, tip, commission, payroll, client mix, cancellation/no-show,
utilisation, popular service, visit frequency and cash-close views. Product
sales and stock are hidden for now.

## 6. Responsive and accessibility review

The live authenticated workspace was reviewed at the current 879×793 in-app
viewport. Location and team fields remain two-column where space permits;
calendar filters stack cleanly, Week remains horizontally scrollable, dialogs
fit within the viewport, bottom navigation stays reachable, and primary touch
targets are at least 44 px. Dialogs have programmatic titles/descriptions,
keyboard Escape handling, focus restoration, persistent validation feedback and
specific destructive-action wording.
